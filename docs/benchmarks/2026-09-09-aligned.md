# Aligned transport measurements and notification validation

Recorded on 9 September 2026 using Chromium 151.0.7922.34, Node 24.20.0, macOS arm64 and an Apple M3 Pro. Both transports use the same public fixture: 10,000 DOM nodes, 200 levels, 20 closed shadow roots and three cross-origin frame levels.

## Method

Each transport runs sequentially with five warm-up iterations and 30 measured samples per operation and selector. A workflow fills the deep input, clicks its save control and captures an interactive snapshot. A matching batch performs the same two actions with observation. Persistent-overlay clicks are measured separately. Reference-based actions refresh disposable references after each observation; locator-based actions use identical exact accessible names.

All timings are milliseconds. The action gate is p95 ≤500 ms; the snapshot gate is p95 ≤1,000 ms. Model time and application loading are excluded. CDB processing and transport round trips are included. Blocked clicks exercise the existing two-second deadline; their duration is not a successful-action speed improvement. Batch limits remain 20 actions and 30 seconds.

The first aligned attempt failed during warm-up because the benchmark reused references invalidated by its own snapshot. The harness now consumes the latest observation. That setup failure is retained in the diagnostic evidence; it produced no measured samples.

[Every measured sample](./2026-09-09-aligned.csv) is retained. [Earlier failed gates and lifecycle runs](./2026-09-09-lifecycle.md) remain unchanged evidence; the new measurements do not erase them.

The Devframe locator-click p95 of 522 ms failed the 500-ms gate. Diagnostics attributed the slow clicks mainly to discovery: one 521-ms sample spent 420 ms discovering candidates and 84 ms checking actionability. Independent frame accessibility queries ran serially. The slowest sample spent 609 ms in one frame's accessibility query alone.

Discovery now reads up to four independent frame contexts concurrently, retaining frame order and awaiting all candidates before deciding uniqueness. No cross-action DOM cache, relaxed checks, input replay or deadline change was introduced.

## Recorded machine load

The final attributed WebSocket run stopped after 279 of 300 measurements when a blocked click exhausted its actionability deadline before establishing the covering ancestor. Its pending command was `Page.getFrameTree`; input was not dispatched. The locator summary is incomplete because the selector's blocked-action loop did not finish. This failed run must not be replaced with an earlier passing result.

The final attributed Devframe run completed all 300 measurements, but both snapshot gates failed at approximately 1,640 ms. Chrome debugger binding timings included a 2,390-ms `Accessibility.getFullAXTree`, a 1,308-ms `Accessibility.disable`, a 1,034-ms `Page.enable` and a 1,034-ms `Page.getFrameTree`. These measurements establish browser-boundary delays, not their underlying cause. CDB command round trips also include transport, serialization, authority and artifact work; the remaining time is not fully attributed.

A concurrent process inspection found an unrelated desktop renderer consuming about 569% CPU and 15.8% of system memory. Subsequent desktop activity also varied. This is observed contention, not proof that it explains every delay. No process or profile changes were made. Performance validation remains incomplete; further acceptance measurements require a settled environment.

## Notification verification

The exact hub-ui 0.9.10 patch from Devframe PR #375 is exercised in the installed embedded and standalone browser bundles. Both hosts pass deletion, full reconciliation, changed descriptions, unchanged publications, manual dismissal and intentional resurfacing. Eight page-script tests cover direct Accept/default Review, stable message registrations, count changes, serialized updates and creation/expiry/disposal races. The MCP package's 67 unit regressions also pass.

Workspace patches do not propagate to consumers of published CDB packages. See [patch provenance and removal conditions](../../patches/README.md).

## Follow-up lifecycle matrix

The independent 30-cycle matrix stopped in cycle 6 after 23 successful scenarios. Navigation, reconnect and cancellation each completed six times; revocation/reapproval completed five times, then its next click timed out before input. At failure, discovery had taken 1,150 ms and actionability 917 ms, with `Page.getLayoutMetrics` pending. Load rose from 12.6 / 12.0 / 11.3 to 44.7 / 18.8 / 13.8.

[All follow-up lifecycle samples](./2026-09-09-followup-lifecycle.csv) retain the failure. The intended 120-scenario gate is not satisfied. The surrounding Chromium integration checks reached this matrix successfully, including closed shadow roots, cross-origin frames, overlays, overlapping grants and ordinary shared RPC traffic. No crash was observed; the intermittent stall cause remains unresolved.
